Chapter 4

Reshaping the SDLC: Agentic DevOps and the RPI Cadence in Practice

Primitives come alive across Plan → Design → Develop → Test → Release → Maintain. Explore the full lifecycle through FlowDesk, an agentic IT copilot built with HVE.

🏢 The Running Scenario: FlowDesk

FlowDesk is an agentic IT service copilot for Northwind Logistics (~4,000 employees). It triages tickets, drafts resolutions, escalates with context, and feeds the knowledge base — all inside Microsoft Teams + a custom ITSM backend via MCP.

1 The RPI Cadence

Inside every SDLC phase, agents follow the same three-beat cadence: Research → Plan → Implement. Humans approve the plan; agents do the work.

2 Six SDLC Phases, Reimagined

📝

Phase 1 — Plan

Meeting notes → Reviewable specs in an afternoon

The kickoff recording becomes a structured specification — and then reviewable user stories — via primitives. The product manager edits rather than writes from scratch.

Prompt: meeting-to-spec Prompt: spec-to-stories MCP: Azure DevOps
🏗️

Phase 2 — Design

Spec → Architecture diagrams + ADR + cost estimate

The architect agent turns the approved spec into reviewable artifacts: a Mermaid C4 diagram, an ADR, and a BoQ cost estimate — all reviewed through a standard PR.

Prompt: spec-to-architecture Prompt: architecture-to-BoQ MCP: Mermaid
💻

Phase 3 — Develop

Design → Running code with bounded agents

Development agents read the approved architecture and produce small, reviewable PRs. The backend-dev agent can't deploy; the infra-dev agent can't touch production. Each has scoped permissions.

Instructions: copilot-instruction Skill: agent-framework-scaffold Agent: backend-dev Agent: infra-dev Prompt: scaffold-microservice
🧪

Phase 4 — Test

Backlog-driven test design + agent flow validation

Tests run alongside development. The spec-to-test-plan prompt is the RPI Plan gate — the tech lead reviews it before test code is generated. Specialized agents handle unit tests and agent trace tests.

Prompt: spec-to-test-plan Agent: test-dev Agent: scenario-test-author MCP: Azure DevOps
🚀

Phase 5 — Release

CI/CD as an active safety system, not a passive script

The release-captain agent composes release notes, detects anomalies (coverage drops, unusual files, new MCP servers), and halts the pipeline when something looks wrong — requiring explicit human confirmation to proceed.

Agent: release-captain Hook: secrets-scanner Skill: deploy-to-aca MCP: GitHub
🔧

Phase 6 — Maintain

Codebase exploration, bug triage, automated PR reviews

Maintenance cost flattens over time. New joiners onboard against a codebase-explorer agent. Every PR is pre-reviewed by an agent before a human arrives. Bugs are triaged and hypothesized automatically.

Agent: codebase-explorer Agent: bug-triage Agent: pr-reviewer Hook: pr-review-bot

3 Agentic DevOps Principles

The through-line across all six phases.

🎯

Outcome-Driven Execution

Define goals and constraints; agents decide how to achieve them based on context.

🛡️

Autonomous within Guardrails

Agents plan, execute, and optimize independently — but within governance boundaries (policies, approvals, auditability).

🧠

Context-Aware Reasoning

Unlike CI/CD scripts, agents interpret real-time system state, dependencies, and history to adapt dynamically.

🔄

Closed-Loop Learning

Observe → Plan → Act → Learn. Systems improve over time through feedback from deployments and operations.

🤝

Collaborative Systems

Multiple specialized agents coordinate across the SDLC, working alongside humans rather than replacing them.
