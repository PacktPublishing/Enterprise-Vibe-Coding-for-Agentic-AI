From One-Off Prompts to Repeatable Engineering

Someone types a prompt and gets a great result. A colleague tries the same prompt — subtly different output. A week later, nobody remembers the exact wording. The output was useful, but the process is folklore, not engineering.

A primitive is a small, reusable file — typically Markdown or YAML — that tells an agent how to behave, what tools it can touch, what "good" looks like, and when to escalate. Primitives are composable and surface-agnostic.

💡 Chapter Takeaway

Primitives turn one-off prompting into repeatable engineering. Instructions set the rules, Prompts structure the tasks, Agents define who does the work, Skills package the how-to, Hooks enforce guardrails, and MCP connects to the world. They create the most value when composed together — a single request can activate multiple layers of guidance, automation, and control.
